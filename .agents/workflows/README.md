# Workflows

Carga perezosa: se lee el que corresponde a la misión, no los seis. Lista abierta —
el esqueleto es universal, las especificidades van a la capa de proyecto.

| Workflow | Cuándo |
|---|---|
| `instruccion.md` | abrir una misión: convertir una intención en orden ejecutable |
| `cierre.md` | terminarla |
| `diagnostico.md` | algo no funciona y hay que encontrar por qué |
| `feedback.md` | llega retroalimentación y hay que convertirla en trabajo |
| `migracion-estandar.md` | el estándar subió de versión |
| `reversion.md` | deshacer una misión ya commiteada |
| `intervencion.md` | un agente corrige el trabajo de otro — **NO NORMATIVO** |

Los seis primeros son normativos. **`intervencion.md` no lo es** y no forma parte de
v0.1.0: es el único que no viene de v0.2.1 —el documento maestro se escribió para un
agente por misión— y depende de un prerrequisito que todavía no existe, la certificación
externa de OPS-07. Sin árbitro fuera del alcance de los agentes, un protocolo de
intervención es agentes vigilando agentes. Queda escrito y fechado para que el diseño no
se pierda; ningún verificador lo comprueba y ningún cierre falla por incumplirlo
(D-C25).
